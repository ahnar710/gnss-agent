# 产品需求文档（PRD）— GNSS 文献调研 Agent

> 版本：v0.1（MVP） · 状态：设计确认中 · 作者：产品团队

## 1. 产品概述

**一句话定义**：一款**完全本地运行**的网页应用，GNSS 测试行业的产品经理输入一句调研主题，Agent 便自动完成"检索 → 深读 → 分析 → 报告"全流程，24 小时内交付一份 ≥100 篇文献的中文调研报告；用户不点停止，Agent 就持续工作。

**产品形态**：本地网页应用。用户在 Windows（或 Mac）电脑上安装并启动，浏览器打开 `http://127.0.0.1:端口` 使用。所有代码、数据、API Key 均在本机，不经过任何第三方服务器。

**核心价值**：
1. **零门槛**：目标用户不懂编程、不懂检索式，只需说人话。
2. **全流程自动化**：从主题解析到报告成文，固定工作流一次跑完。
3. **深度而非数量**：不是 100 条链接堆砌，而是逐篇深读、归类、总结的研究报告。
4. **持续不中断**：24 小时窗口内持续扩充与深化，直到用户叫停。

## 2. 目标用户与典型场景

### 2.1 用户画像
| 画像 | 说明 |
|---|---|
| 角色 | GNSS 测试设备厂商的产品经理（也可能有研发、市场人员） |
| 能力 | 熟悉 GNSS 业务术语（RTK、完好性、多路径……），但**不懂编程、不懂数据库检索** |
| 环境 | Windows 10/11 办公电脑，可联网，可自费申请大模型 API Key（DeepSeek/OpenAI 等） |
| 诉求 | 快速掌握某个方向的"学术界最新进展"，用于产品规划、竞品分析、标准预研、技术选型 |

### 2.2 典型场景
- **技术趋势调研**：想了解"PPP-RTK 最近三年的研究热点"，决定下一代产品是否上这个方向。
- **竞品技术对标**：竞品宣称的"抗欺骗能力"学术界是怎么定义和验证的？有哪些公开方法？
- **标准/合规预研**：接收机完好性相关标准（RTCA DO-229 等）背后的学术依据是什么？
- **算法选型**：多路径抑制有哪几类方法？各方法的性能上限和工程成本如何？
- **测试方法学**：GNSS 模拟器场景如何设计？硬件在环测试的学术实践有哪些？

## 3. 功能需求

### FR1 新建调研任务
- 用户输入**调研主题**（一句话，自然语言，中英文均可）。
- 可选：补充**方向说明**（背景、关注重点、排除项）、目标篇数（默认 100）、时间范围（默认最近 10 年）、运行时长上限（默认 24 小时）。
- 提供 15 个内置示例主题一键填入。
- 提交后任务立即自动开始，无需任何其他操作。

### FR2 自动检索与扩源
- 系统将主题解析为检索策略（中英文关键词组合），并行检索多个免费开放学术源：OpenAlex、arXiv、Semantic Scholar、Crossref。
- 自动去重（DOI/标题归一化）、按相关性与引用量排序。
- 若达标篇数不足，自动**扩展检索**：换关键词组合、挖掘高相关论文的引用网络、滑动时间窗口，循环迭代。

### FR3 逐篇深读
- 对高相关论文，由大模型逐篇提炼：研究问题、方法、关键结论、与 GNSS 测试的相关性、所属子领域。
- 深读结果以结构化数据存储，作为报告素材。

### FR4 报告生成
- 实时进度可见：已检索 / 已判定相关 / 已深读篇数。
- 达到目标篇数或用户停止或超时后，生成中文调研报告（Markdown，可导出/打印）：
  - 调研概述与统计（检索范围、来源分布、时间分布）
  - 子领域聚类与热度分析
  - 逐篇结构化摘要（按子领域分组）
  - 研究趋势与空白（缺口）分析
  - 参考文献列表（含 DOI/链接）
- 报告在任务运行期间**持续更新**（每积累一批新深读就重生成），用户随时可查看当前版本。

### FR5 持续运行与停止
- 达标后**不自动结束**：进入"过载模式"继续扩展检索、深读新论文、刷新报告，直到用户点"停止"或达到时间上限。
- 用户可随时点"停止"：优雅停止（完成当前步骤后生成最终报告），任务状态变为"已停止"。

### FR6 断点续跑
- 任务进度、论文、日志全部落盘（SQLite）。
- 关闭浏览器、重启电脑、程序崩溃后重新打开，进行中的任务**自动恢复继续**。
- 已检索过的查询不重复执行（幂等）。

### FR7 本地设置（自带 Key）
- 用户在设置页配置：大模型 API Base URL、API Key、模型名（兼容 DeepSeek / OpenAI / 通义千问 / Ollama 等 OpenAI 兼容接口）。
- Key 仅保存在本机数据库中，绝不外发；产品无任何云端组件。
- 未配置 Key 时无法启动任务，界面给出引导。

### FR8 设置项
- 默认目标篇数、默认时间上限、默认时间范围、并发度（高级）、启用/停用某个文献源、是否启用 LLM 打分阈值等。

## 4. 固定工作流（状态机）

```
用户输入主题
   │
   ▼
[1 主题解析] 自然语言 → 检索意图（中英关键词 × 子领域 × 时间范围）
   │
   ▼
[2 多源检索] OpenAlex / arXiv / Semantic Scholar / Crossref 并行抓取
   │
   ▼
[3 去重归一] DOI/标题去重，合并元数据
   │
   ▼
[4 相关性打分] LLM 逐篇打分 → 保留高相关（阈值可配）
   │
   ▼
[5 逐篇深读] LLM 提炼结构化摘要（问题/方法/结论/相关性/子领域）
   │
   ▼
[6 达标检查] 已深读 ≥ 目标篇数？
   ├─ 否 → [7 扩展检索] 新关键词组合 / 引用网络挖掘 → 回到 2
   └─ 是 → [8 过载模式] 继续扩展+深读+刷新报告，直到用户停止或超时
   │
   ▼
[9 报告生成] 中文调研报告（持续更新，最终版落盘）
```

任务状态：`running → (completed | stopped | error)`；`running` 状态可被持久化并在重启后恢复。

## 5. 验收标准（MVP）

| # | 验收项 | 标准 |
|---|---|---|
| A1 | 主题输入 | 输入一句中文/英文主题，任务自动开始，全程无需人工干预 |
| A2 | 达标产出 | 24 小时内产出 ≥100 篇相关文献并逐篇深读 |
| A3 | 报告质量 | 报告含概述/聚类/逐篇摘要/趋势与缺口/参考文献，可直接用于产品决策 |
| A4 | 不点不停 | 达标后继续工作；只有用户点"停止"或超时才会结束 |
| A5 | 断点续跑 | 运行中关闭应用再打开，任务自动恢复，不重复已做工作 |
| A6 | 本地隐私 | API Key 只存本机；全链路无第三方服务器 |
| A7 | 零门槛 | 非技术人员按三步完成：双击安装器 → 设置页填 Key → 输入主题提问 |
| A8 | 跨平台 | 同一代码库在 macOS（开发）与 Windows 10/11（用户）运行；Windows 交付一键安装包（免 Python、无黑窗口、自动打开浏览器） |
| A9 | 单实例/自检 | 重复双击不启动第二个实例；端口被占自动换；启动异常有日志与弹窗提示 |

## 6. 本期非目标（Non-goals）
- 不接入需付费/无官方 API 的源（IEEE、Elsevier、CNKI、Google Scholar 爬虫）——列入路线图，以可选插件形式扩展。
- 不做多用户协作/账号体系/云端同步。
- 不做移动端。
- 不承诺"引文 100% 可下载全文"（开放 API 元数据为主，全文抓取视源许可而定）。

## 7. 风险与对策
| 风险 | 影响 | 对策 |
|---|---|---|
| 学术源限流/宕机 | 检索变慢或中断 | 多源冗余 + 指数退避重试 + 任务状态可恢复 |
| LLM 输出幻觉（虚构文献/摘要失真） | 报告可信度 | 只对真实抓取到的文献做深读；提示词约束"不得编造未提供的元数据"；保留原文链接供核验 |
| API 成本不可控（24h 持续调用） | 用户花费 | 深读优先队列 + 批量打分降本；设置页显示预估消耗；时间上限可配 |
| 关键词覆盖不足 | 漏检 | 内置 GNSS 领域词库 + LLM 自动扩展 + 引用网络挖掘 |
| 合规（爬取条款） | 封禁/法律 | 仅用官方开放 API，遵守各源 ToS；爬虫类源默认关闭 |
| Windows 部署差异 | 安装失败 | PyInstaller 单目录打包 + Inno Setup 安装器 + 启动自检（单实例/端口/网络/数据目录）+ 错误日志与弹窗 + 排障文档（docs/WINDOWS_DELIVERY.md） |

## 8. 上线后度量
- 任务达标率（24h 内 ≥100 篇的比例）
- 平均达标耗时、平均深读篇数/小时
- 报告可用性评分（用户问卷：可直接使用/需补充/不可用）
- 单任务 API 平均成本
- 断点续跑成功率（重启后恢复且不丢进度的比例）
